Checker development tests

First run npm ci --ignore-scripts --omit=optional and npm run dependencies to prepare the pinned browser libraries. From the repository root, run python tests/serve.py and open the local address it prints. Stop the server with Ctrl+C.

These suites need the existing ignored examples in TestFiles/. They check the submission checker; they do not run student Java code.

  • All generated examples — archive, project and report workers.
  • Report regression tests — synthetic cases and reports from TestFiles/Real/.
  • PDF regression tests — readability, text and limits.

Run the ZIP regression tests with node --test tests/checker.test.mjs using Node 22.18 or later. npm test also checks the deployment output.

npm run build prepares _site/ for GitHub Pages. Only the student pages, checker code, styling and required library files are published. The generated checker/vendor/, node_modules/ and _site/ directories are ignored by Git.

Complete expected findings live in tests/fixtures.json. Run python tests/fixture-guides.py --check to check the private guides, or python tests/fixture-guides.py --write to regenerate them after intentional expectation changes.

Generators are in tests/generators/: archives.py, netbeans.py, pdf.py and reports.py. Use --help for dependencies and arguments. Each requires a new --output directory and refuses to overwrite existing examples. The NetBeans generator requires the original starter ZIP; no generator reads student submissions.

To check rebuilt examples without replacing the originals, run python tests/serve.py --generated-root PATH, where PATH contains Archive-errors/, NetBeans-exports/ and Reports/. The PDF and document generators create separate output directories; combine their example files into a new Reports/ directory for the full suite.

Check the Java turn-test contract with python tests/java-turn.py --java PATH_TO_JAVA --starter PATH_TO_FoPCW2025.zip. This runs the untouched starter and controlled movement variants in temporary storage.
